# Luma Card Craft · 3D 镭射卡工坊

把角色和场景做成值得收藏的画面，再按所需交付增加主题边框、视角镭射和可读的层次。支持静态插画、现有产品内的局部修订，以及独立 Blender / Three.js 卡牌工程。

本 Skill 整合 RuiC Card Skill 的 MIT 流水线与新的制作经验。先读 [许可与来源](NOTICE.md)：上游代码和复制参考保留 MIT，新增指导采用 CC BY-NC-SA 4.0；不能把上游已有的商业使用权改写成禁商用。

## 先选择交付方式

用户已确定的范围优先；不要为了“完整流水线”给一张静态插画强加 Blender，也不要把现有产品修复变成另一个演示网站。

- **插画 / 边框**：完成画面、真实透明边框和必要的来源记录即可。使用实际可用的图像工具；不能静默改用另一个收费服务。
- **已有卡牌升级**：沿用真实渲染入口和资源注册，保留原图、卡背、版本身份及已完成的材质。先查缺的是材质、配准、层次还是几何，避免重复叠框。
- **独立交互卡**：可使用本包的四层 Blender / Three.js 基线，见下文。它需要主体、背景、线稿和可见文字层，不适用于所有无字卡、独立卡背或语义浮雕方案；这种需求应调整渲染器及验证，不能伪造空层来通过校验。

开始画图时读 [插画质量](references/illustration-quality.md)；准备分层时读 [图层与参考](references/art-direction.md)；高级深度、版本和展示问题查 [制作检查表](references/production-checklist.md)。复制参考中的 Luma 玩法、数量和历史默认仅是产品案例，不能代替当前任务的合同。

## 画面与系列

给每张卡一个可观察的事件：在做什么、注意什么、如何回应。系列计划至少明确身份不变量、所在世界、镜头、动作、视线目标、情绪、轮廓和色调。

保留角色身份不等于复用同一个正脸、歪头、交叉腿和微笑。可以侧脸、背影、俯视或环境远景，但也不要把全系列机械地改成背影。服装或天气变化不能代替新的构图。

先检查颈部与肩线、骨盆与双腿、重心和手部接触，再欣赏细节。跟踪每条肢体的完整连接；悬空的脚可以自然悬空，不要补一块石头来掩盖姿态问题。局部修改应保留已批准的其他部分。

## 边框、镭射和深度

- 先看真正的卡背与系列成品，再设计边框。提取材料、纹样节奏和色调；每张按画面留出脸、手、头饰与道具空间。纤细连续的刻线、完整小叶片与非对称点缀优于粗链条和角落大珠宝。
- 让画面占主体。横版卡按自己的长宽比展示，不塞入竖版黑框；少量卡片应居中。检查实际缩略尺寸，不能只审一个放大的空边框。
- 镭射相位跟视角变化；把明显效果限制在金属、晶体、湿面、织物或纹饰，保持皮肤与主要表情可读。静态原画必须是独立清晰的选择。
- 区分整卡旋转、卡片厚度、边框浮雕、图层视差和内容几何。说明实际达到哪一种；CSS 倾斜或亮度法线不等于人物雕塑。
- 有层次的交付需要真实配准的层和正确 Alpha。透明洞应保留；背景不能随头发或饰件一起抠走。不要用整图亮度直接推断身体深度。

## 独立工程基线

将输出放在用户项目里，保持本 Skill 不含生成作品。依赖为 Python 3 + Pillow、Node.js/npm 和 Blender；已有 Blender 可通过 `--blender` 指定。没有 Blender 时，脚本按官方 SHA-256 下载到输出项目的 `tools/`，不改变系统设置。Bun 只在重建网页 JavaScript bundle 时使用；本包保留了可运行的预构建文本 bundle。

1. 根据 [配置示例](references/config.example.json) 创建输出项目的 `card-config.json`。
2. 在输出项目的 `assets/` 准备同一画布的 `subject.png`、`background.png`、`lineart.png`、`text.png`。主体与文字必须有真实透明 Alpha 和实际可见内容，线稿为配准的白底深色轮廓。PNG 后缀或绘制的棋盘格不能证明透明。
3. 在 Skill 目录执行：

   ```sh
   python3 scripts/validate_assets.py /path/to/card-project
   python3 scripts/run_pipeline.py --project /path/to/card-project
   # 或使用已有 Blender：
   python3 scripts/run_pipeline.py --project /path/to/card-project --blender /path/to/blender
   ```

   如果未提供文字层，基线脚本会排出配置中的文字，并带固定模板标记；不要把该默认行为误称为无字卡支持。
4. 启动网页：

   ```sh
   node /path/to/card-project/web/server.mjs
   ```

   查看终端实际返回的本地地址。若修改了网页源码，在生成的 `web/` 目录安装依赖并执行 `bash bundle.sh` 重建；Bun 缺失时应明确告知，不能使用旧 bundle 声称修改已生效。
5. 实测 [验证清单](references/verification.md) 中的前后面、双向倾斜、拖动、缩放、材质、窄屏和减少动态。网页回退到 CSS 层叠模式时如实标记，不称为 WebGL 成功。

基线导出真实卡片几何和材质角色；Blender 自定义节点不会经 glTF 自动变成相同网页材质，Three.js 使用自己的 GLSL 重建。

## 技术不变量

- Blender 卡面使用 XY 网格、物体 X=90°，保留该物体变换；不要用改顶点冒充应用旋转。
- 视角方向进入统一卡片坐标系，除以有界法向分量，再按有符号深度偏移 UV。glTF 的 Y-up 转换后使用卡片 root 坐标系，V 坐标只恢复一次。
- 主体 Alpha 参与面材质合成，背面和侧边保持独立材质角色。原图、边框、人物、景物的几何和法线不能互相冒充。
- 蒙版与深度支持是两个问题：细柄或书页边缘若撕裂，检查透明边界外插值，不要只侵蚀 Alpha 或无上限增加面数。
- 大角度时检查前景层是否像悬空薄片；侧视过渡可按设计平滑回归印刷面，普通角度仍须保留真实层次。
- 原画静态视图需要原画呈现及必要边框；关闭动态时不能错误地清掉 intrinsic frame，也不能保留视角镭射遮住原图。

## 验证与交付

每次更换源图创建新版本，并重新核对受影响的 RGB、Alpha、蒙版、深度、纹理、几何及哈希绑定。不要覆盖旧完成版或把新图套在旧验收结果上。

在实际浏览器查看完整画面，检查 shader 编译、资源请求、双向视差、窄屏、横卡、背面和关闭后 GPU 释放。ready 标志、维度、非零蒙版与唯一哈希是技术证据，不能单独证明美观、解剖或实际安装完成。

交付时列明实际文件、可运行地址、使用方式和验证范围。生成图像包含 AI 辅助时如实说明；保留上游许可及展示图授权边界。没有用户要求，不上传作品、公开仓库或发布应用。

本仓库的说明与案例位于仓库根目录的 `docs/`；安装此 Skill 后即使没有该目录，上述 references 仍可独立使用。分享 Skill 可执行 `python3 scripts/package_skill.py <skill-folder> --out <outside-folder>/luma-card-craft.zip`，只打包文本，不包含卡图、模型、视频、凭据或运行缓存。
